Git cloning and direct raw HTTP access to tasm2-nextos returned 404/authentication failures in this environment, including after the user's requested retry. Browser-backed GitHub retrieval did expose the main tree and several actual source files; some large files were truncated. The wrapper does not depend on a local NextOS checkout. Unavailable source portions were investigated through the supplied 1.2.8d files and the public release loader. No NextOS Linux/X11/SDL implementation is linked into this Switch port.

The second supplied Switch crash led to inspection of the public release loader's `asm2_installer_compat_initialize` (four allocations, complete/partial-state and relocation checks). The original local 1.2.8d ELF independently confirms the four BSS/GOT destinations and one-entry native count/worker allocation paths. Only that generic preparation pattern is used; no NextOS hook or guest instruction skip is introduced for this failure.

The current Shop investigation also read the public `asm2_127/src/shop_compat.c` implementation through browser-backed GitHub retrieval and inspected the local release loader's compatibility tick. Its two-schema readiness and native parser/completion pattern guided the investigation. All offsets, map layouts, parser/counter calls and state writes used here were independently disassembled in the owner's hash-checked 1.2.8d ELF. The costume names and Scarlet mapping were verified in its own game-data files; no NextOS entitlement patch or Linux interface was copied.
